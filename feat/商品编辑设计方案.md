# CFFK 商品编辑设计方案

> **文档状态：设计完成，待开发**
>
> 本方案以 `docs/dev.md`、`docs/components.md` 为强约束，参考 `edgeKey/pages/admin/products/new`、`ProductForm.vue` 和 `RichTextEditor.vue` 的业务能力，但不照搬其独立页面、DaisyUI、Prisma、Auth.js 或任意 HTML 编辑方式。
>
> CFFK 是未上线的新项目，不为当前纯文本商品描述、前端分页接口或旧表单状态编写兼容、迁移和双写代码。开发时直接收敛到本方案定义的最终结构。

## 1. 背景与现状

CFFK 当前商品管理正式路由为 `/${ADMIN_PATH}/catalog/products`，实现集中在：

- `pages/@adminPath/catalog/products/+Page.vue`：列表、筛选、前端分页、创建/编辑 Dialog 和表单状态；
- `server/catalog/admin.telefunc.ts`：分类与商品管理查询、保存和状态切换；
- `database/drizzle/schema.ts`：`category`、`product` 等数据表；
- `pages/product/@slug/+Page.vue`：公开商品详情和下单表单；
- `server/catalog/public.ts`：公开商品列表和详情投影。

当前商品表单已经覆盖大部分业务字段：

- 名称、Slug、副标题、分类和封面；
- 描述、购买说明；
- 价格、排序、最小和最大购买数；
- 自动卡密、固定内容、人工发货和物流发货；
- 固定交付内容、发货提示和实物库存；
- 草稿、上架、下架；
- 联系方式要求和库存展示开关。

因此本功能不以增加大量商品字段为目标，而是解决以下问题：

1. 创建和编辑字段平铺在 `max-w-2xl` 长 Dialog 中，缺少清晰的信息分区。
2. 商品描述是普通 `Textarea`，公开详情按纯文本展示。
3. 表单没有使用规范要求的 VeeValidate、Zod 和 shadcn-vue `Field`。
4. 保存、上下架等一次性错误使用页面级 `Alert`，不符合统一 Toast 规范。
5. 有未保存输入时仍可能通过遮罩或 `Escape` 意外关闭。
6. 列表一次返回全部商品，再由浏览器搜索、筛选和分页。
7. 列表响应携带完整描述、购买说明、发货提示和固定交付内容等非列表字段。
8. 创建/编辑直接复用列表行数据，没有按点击编辑后单独加载完整商品。
9. 商品详情尚无安全 HTML 渲染和统一富文本排版。
10. 当前页面文件同时承担列表、表单、请求、转换和 UI，后续难以维护。

## 2. edgeKey 参考结论

### 2.1 采用的业务能力

参考 edgeKey 完整商品表单，CFFK 采用以下能力：

- 商品信息按语义分组；
- 商品描述使用富文本编辑器；
- 支持标题、段落、粗体、斜体、引用、列表、链接、图片、分割线、撤销和重做；
- 商品封面和描述图片可复用媒体库；
- 发货方式按业务含义展示说明和条件字段；
- 新建和编辑复用同一套表单 schema、默认值和转换函数；
- 保存前同时进行客户端即时校验和服务端最终校验。

### 2.2 不直接采用的部分

以下 edgeKey 实现不适用于 CFFK：

- 不新增 `/catalog/products/new` 或 `/catalog/products/:id` 独立后台页面；
- 不使用 DaisyUI 或业务页面原生表单控件；
- 不在表单组件内部直接调用业务 Telefunc；
- 不使用 Prisma 或 Auth.js `role=admin`；
- 不开放任意 HTML 源码编辑；
- 不开放任意文字颜色、背景色、字体和字号；
- 不允许 iframe、脚本、内联事件、任意 class/style 或 Base64 图片；
- 不将固定交付内容、发货提示和购买说明改成富文本；
- 不建设管理员多角色、审批或审计系统。

## 3. 设计结论

1. `/catalog/products` 继续作为商品管理唯一正式页面，不新增商品创建或编辑路由。
2. 新增和编辑继续由同一个 `ProductEditorDialog` 承载，符合 `docs/dev.md` 的实体交互规范。
3. Dialog 支持 `quick` 和 `complete` 两种展示模式，但共享同一份表单 schema、默认值、脏状态和保存接口。
4. “快速添加”只创建草稿；“添加商品”和行操作“编辑”进入完整模式。
5. 商品表单统一使用 VeeValidate、Zod、`Field`、`FieldSet`、`FieldLegend`、`FieldDescription` 和 `FieldError`。
6. `description` 定义为经服务端白名单清洗后的商品详情 HTML；其他交付和说明字段继续保存纯文本。
7. 商品描述写入前必须在服务端清洗，公开详情只渲染已经清洗的 HTML。
8. 商品列表改为服务端搜索、筛选和分页，只返回当前页展示字段。
9. 点击编辑后通过单商品管理接口加载完整数据，不从列表响应取得描述和交付全文。
10. 页面负责列表状态、请求和业务反馈；子组件只负责展示、交互、校验状态和事件。
11. 保存、状态切换等短暂反馈统一通过 `runTelefunc()` 和 Sonner Toast；只有无法继续工作的初始加载失败使用页面级 `Alert`。
12. `product.description` 已是 SQLite `text`，本功能不需要新增数据库字段或 SQL migration。

## 4. 目标与非目标

### 4.1 目标

- 提供真正快速的商品草稿创建流程；
- 提供完整、分区清晰的商品创建和编辑体验；
- 建立富文本编辑、服务端清洗、数据库保存和公开安全渲染闭环；
- 统一商品表单类型、默认值、客户端校验和接口转换；
- 将商品列表收敛到项目标准服务端分页契约；
- 防止列表接口泄露固定交付内容等非展示字段；
- 为商品管理 Telefunc 补齐稳定错误码、root 鉴权和服务端校验；
- 保持桌面端、窄屏、键盘操作和无障碍状态可用。

### 4.2 非目标

第一版不实现：

- 独立商品新增或编辑页面；
- 商品多规格、SKU、套餐或属性组合；
- 商品图库和图片排序；
- 富文本视频、iframe、代码执行或任意 HTML；
- 富文本自定义字体、字号、文字颜色或背景色；
- 商品定时上架、审核、审批、版本历史或自动保存；
- 在商品 Dialog 内复制卡密导入和管理功能；
- 为当前开发数据编写旧描述格式兼容代码。

## 5. 后台交互设计

### 5.1 商品列表

页面保持：

```text
AdminPageHeader
AdminDataTable
ProductEditorDialog
MediaPickerDialog（由需要它的表单组件挂载）
```

`AdminPageHeader` 继续从 `lib/admin-navigation.ts` 读取现有 `adminPages.products`，页面不得硬编码 H1 和描述。

列表列建议：

| 字段 | 展示方式 |
| --- | --- |
| 商品名称 | 普通文本 |
| 分类 | 服务端 join 后的 `categoryName` |
| Slug | 等宽小号文本 |
| 价格 | 人民币格式化 |
| 发货方式 | 中文标签 |
| 状态 | `Badge`，上架使用 `secondary`，其他使用 `outline` |

一项业务字段对应一列，不在商品名称单元格堆叠分类、价格和状态。

工具栏分组：

```text
筛选：关键词、分类、状态、搜索、重置
操作：刷新、快速添加、添加商品
```

规则：

- 搜索和重置显式触发请求；
- 修改查询条件或每页数量后重置到第 1 页；
- 宽度不足时允许 `flex-wrap` 换行；
- 列表仅展示当前页服务端返回的 `items`；
- 行操作“编辑”先加载完整商品，再打开完整模式；
- 上架/下架继续作为行操作，必须经服务端状态校验。

### 5.2 快速添加模式

快速添加目标是用最少字段创建可继续完善的草稿。

显示字段：

- 商品名称；
- 分类；
- 价格；
- 发货方式；
- `FIXED_CARD` 时显示固定交付内容；
- `MANUAL` 或 `EXPRESS` 时显示实物库存。

默认值：

```ts
{
  slug: "",                 // 根据名称自动生成
  subtitle: "",
  coverImage: "",
  description: "",
  fixedDeliveryContent: "",
  manualDeliveryHint: "",
  purchaseNote: "",
  isVisibleStock: true,
  isContactRequired: true,
  price: 0,
  status: "DRAFT",
  deliveryType: "CARD_AUTO",
  physicalStock: null,
  minBuy: 1,
  maxBuy: 1,
  sort: 0,
}
```

底部操作：

- 取消；
- 切换到完整配置；
- 创建草稿。

“创建草稿”固定提交 `DRAFT`，不能通过快速模式直接上架。保存成功后关闭 Dialog、显示“商品草稿已创建。”Toast 并刷新列表。

### 5.3 完整模式

完整模式用于“添加商品”和“编辑商品”。Dialog 建议使用 `max-w-5xl`，结构固定为：

```text
DialogHeader
  标题与简短说明
ScrollableContent
  基本信息
  商品媒体
  商品详情
  价格与购买规则
  发货与库存
  发布设置
DialogFooter
  取消
  保存商品
```

要求：

- Dialog 总高度不超过视口；
- 只有内容区滚动；
- Footer 固定在底部；
- 窄屏自动单栏；
- 提交期间禁用提交按钮；
- 表单有未保存输入时，拦截遮罩和 `Escape` 关闭；
- 用户点击取消时，如表单未修改则直接关闭，如已修改则在同一交互内明确确认放弃修改；
- 不使用浏览器 `confirm()`。

### 5.4 表单语义分区

#### 基本信息

- 商品名称；
- 副标题；
- Slug；
- 分类。

Slug 规则：

1. 新建时根据名称自动生成；
2. 用户尚未手动修改 Slug 时，名称变化可继续更新；
3. 用户手动修改后停止自动覆盖；
4. 编辑已有商品时默认保留原 Slug；
5. 服务端负责最终规范化、格式和唯一性校验；
6. 表单显示 `/product/<slug>` 地址预览。

#### 商品媒体

- 商品封面 URL；
- 从媒体库选择；
- 图片预览；
- 允许外部公开 HTTP/HTTPS 图片地址和站内 `/media/proxy/*` 地址。

复用 `components/admin/MediaPickerDialog.vue`，不在商品模块复制上传和媒体管理功能。

#### 商品详情

- `description` 使用 `ProductRichTextEditor`；
- `purchaseNote` 继续使用 `Textarea`；
- 购买说明应明确用于下单前持续展示，不作为交付内容。

#### 价格与购买规则

- 价格；
- 最小购买数；
- 最大购买数；
- 排序。

第一版建议后台以“元”输入，表单模型使用精确字符串或经过约束的两位小数值，提交前转换为分；服务端接口继续接收整数分。必须避免浮点误差，并校验：

- 金额不小于 0；
- 最多两位小数；
- 转换后为安全非负整数；
- `maxBuy >= minBuy >= 1`；
- 排序为非负整数。

#### 发货与库存

发货方式使用项目统一 `RadioGroup`；如果尚未存在，先通过 shadcn-vue CLI 添加并按项目风格封装，不在业务页面直接手写原生 radio。

| 类型 | 说明 | 条件字段 |
| --- | --- | --- |
| `CARD_AUTO` | 从未售卡密库存自动分配 | 已保存商品展示卡密库存摘要和管理入口 |
| `FIXED_CARD` | 每次支付后发送同一份固定内容 | 固定交付内容 |
| `MANUAL` | 支付后由管理员填写发货结果 | 实物库存、人工发货提示 |
| `EXPRESS` | 支付后由管理员安排物流 | 实物库存、物流发货提示 |

卡密管理是独立模块。新商品未产生 ID 时只显示“保存商品后可以导入卡密库存”，不在商品 Dialog 内实现卡密导入。

#### 发布设置

- 状态：草稿、上架、下架；
- 下单时必须填写联系方式；
- 前台展示库存。

布尔配置统一使用带关联文字的 `Switch`。上架时执行比保存草稿更严格的完整性校验。

## 6. 表单状态与校验

### 6.1 页面局部表单模块

建议新增：

```text
pages/@adminPath/catalog/products/product-form.ts
```

职责：

- `ProductFormValues` 类型；
- `productFormSchema`；
- 默认值生成；
- 管理详情到表单值的转换；
- 表单值到保存输入的转换；
- 金额元/分转换；
- Slug 客户端生成辅助函数。

不要继续在页面中维护超长 `reactive({...})`、`Object.assign()` 和重复字段映射。

### 6.2 客户端 schema

商品表单必须使用：

- `vee-validate/useForm()`；
- `zod`；
- `@vee-validate/zod/toTypedSchema()`；
- `Field as VeeField`；
- `Field`、`FieldLabel`、`FieldDescription`、`FieldError`；
- `FieldGroup`、`FieldSet`、`FieldLegend`、`FieldSeparator`。

最低校验：

- 商品名称必填并限制长度；
- 分类 ID 为正整数；
- Slug 符合允许字符和长度；
- 封面 URL/站内路径格式合法；
- 金额合法且最多两位小数；
- 最小/最大购买数合法；
- 排序为非负整数；
- 固定内容上架时交付内容必填；
- 实物库存为空或非负整数；
- 描述、购买说明和发货说明限制最大长度。

表单使用 `novalidate`。客户端校验只负责即时反馈，服务端必须重复权限、格式、长度和业务状态校验。

### 6.3 重置和脏状态

- 新建、模式切换和编辑数据加载完成后使用 `resetForm({ values })`；
- 不直接修改局部对象造成 VeeValidate 状态不同步；
- 使用 `meta.dirty` 判断未保存修改；
- 保存成功后关闭 Dialog，再重置表单；
- 取消只关闭，不提交；
- 从快速模式切换完整模式时保留已输入值。

## 7. 富文本编辑器

### 7.1 组件位置与职责

第一版只供商品模块使用，按 `docs/components.md` 放在页面目录：

```text
pages/@adminPath/catalog/products/ProductRichTextEditor.vue
```

组件只负责：

- 接收 `modelValue`；
- 发出 `update:modelValue`；
- 富文本编辑器和工具栏交互；
- 从 `MediaPickerDialog` 获取图片 URL 后插入文档；
- 正确销毁编辑器实例。

组件不负责：

- root 鉴权；
- 保存商品；
- 调用商品 Telefunc；
- 判断商品是否可上架；
- 显示业务错误 Toast。

若未来至少两个模块复用同一编辑器，再提升到 `components/admin`，并同步补充 `docs/components.md`。

### 7.2 第一版工具栏

支持：

- 正文、二级标题、三级标题；
- 粗体、斜体；
- 引用；
- 有序列表、无序列表；
- 链接、移除链接；
- 媒体库图片；
- 分割线；
- 撤销、重做；
- 清除格式。

不支持：

- HTML 源码模式；
- 任意文字颜色和背景色；
- 自定义字体和字号；
- iframe、视频、object、embed；
- Base64 图片；
- 自定义 class/style；
- 任意文件附件。

这既降低存储型 XSS 风险，也避免富文本破坏 CFFK 的黑白灰和品牌色规范。

### 7.3 Tiptap 依赖

建议按实际能力引入最小依赖集：

```text
@tiptap/vue-3
@tiptap/starter-kit
@tiptap/extension-link
@tiptap/extension-image
@tiptap/extension-placeholder
```

版本应与项目当前 Vue、Vite 和 Bun 环境兼容。安装后必须通过 Worker 目标构建，不仅验证浏览器开发模式。

## 8. 富文本存储与安全

### 8.1 存储格式

`database/drizzle/schema.ts` 已有：

```ts
description: text("description")
```

不新增 `descriptionHtml` 或格式版本字段。`description` 的最终业务含义固定为：

> 经服务端白名单清洗后的商品详情 HTML；空内容保存为 `null`。

CFFK 未上线，不编写纯文本兼容检测、双格式渲染或迁移脚本。

### 8.2 服务端清洗

建议新增：

```text
server/catalog/product-description.ts
```

提供纯函数：

```ts
sanitizeProductDescription(html: string): string | null
```

允许标签：

```text
p, br, h2, h3, strong, em, blockquote,
ul, ol, li, a, img, hr
```

允许属性：

- `a`：`href`、受控 `target`、服务端补充的 `rel`；
- `img`：`src`、`alt`、`title`。

允许 URL：

- 链接：`http:`、`https:`、`mailto:`；
- 图片：`http:`、`https:`、站内 `/media/proxy/*`。

必须移除或拒绝：

- `script`、`style`、`iframe`、`object`、`embed`、`form`；
- 所有 `on*` 事件属性；
- `javascript:`、危险 `data:` URL；
- 任意内联 `style` 和 `class`；
- 非白名单标签和属性；
- Base64 图片。

外部新窗口链接必须具有：

```html
rel="noopener noreferrer"
```

清洗器必须兼容 Cloudflare Workers，不得依赖 Node.js JSDOM、浏览器 `window` 或只在 DOM 环境可用的实现。依赖选择需经过 `bun run build` 验证。

### 8.3 长度限制

必须同时限制：

- 提交前原始 HTML 长度；
- 清洗后 HTML 长度；
- 链接和图片 URL 长度；
- `alt`、`title` 等属性长度。

具体上限在实现时集中定义为服务端常量并由客户端 schema复用或镜像，不能散落在页面。服务端限制是最终边界。

## 9. 公开商品详情

`pages/product/@slug/+Page.vue` 当前按纯文本插值渲染描述，改造后使用：

```vue
<div
  v-if="data.description"
  class="product-rich-content"
  v-html="data.description"
/>
```

前提是管理保存入口已经强制执行服务端清洗。公开读取接口不接受客户端 HTML，也不负责补救管理端绕过清洗的写入路径。

增加统一排版：

- `h2`、`h3` 层级和间距；
- 段落行高；
- 列表缩进；
- 引用边框和静态灰色背景；
- 链接使用品牌蓝色；
- 图片 `max-width: 100%`、保持比例并使用圆角边框；
- 分割线使用统一边框色；
- 深色模式保持可读性。

富文本自身不携带主题色和布局 class。

公开商品详情还应持续展示适用的纯文本字段：

- 购买说明；
- 人工/物流发货提示；
- 库存和购买限制。

具体位置由现有详情布局统一设计，不能把固定交付内容公开展示。

## 10. Telefunc 接口契约

### 10.1 商品列表

将当前全量 `onGetCatalogAdminData()` 收敛为服务端分页商品列表接口。建议契约：

```ts
type ProductListQuery = {
  keyword?: string;
  categoryId?: number;
  status?: ProductStatus;
  page?: number;
  pageSize?: number;
};

type ProductListResult = {
  items: ProductListItem[];
  total: number;
  page: number;
  pageSize: number;
  categories: Array<{ id: number; name: string }>;
};
```

分页校正遵循 `docs/dev.md`：

```ts
const page = Math.max(1, Math.floor(input.page ?? 1));
const pageSize = Math.min(100, Math.max(10, Math.floor(input.pageSize ?? 20)));
```

`ProductListItem` 只返回列表展示所需字段，不返回：

- `description`；
- `fixedDeliveryContent`；
- `manualDeliveryHint`；
- `purchaseNote`。

关键词搜索名称和 Slug；分类、状态和数字参数在服务端验证。`total` 是当前筛选条件下总数。

### 10.2 单商品管理详情

新增：

```ts
onGetProductAdminDetail(input: { id: number })
```

只在点击编辑后加载完整商品。服务端校验唯一 root、正整数 ID 和商品存在性。

可附带与编辑直接相关的非敏感摘要，例如自动卡密可用库存数量；不得返回卡密全文。

### 10.3 保存商品

保留一个创建/编辑共用的：

```ts
onSaveProduct(input)
```

服务端必须：

- 校验唯一 root；
- 验证输入对象、枚举、ID、长度和整数；
- 验证分类存在且可用于商品；
- 规范化名称、Slug、URL 和可选文本；
- 清洗 `description` HTML；
- 校验发货方式和条件字段；
- 校验价格、库存和购买范围；
- 上架时执行完整性校验；
- 使用数据库唯一约束保证 Slug 最终唯一；
- 新建和更新均返回保存后的完整管理详情投影。

快速添加也调用该接口，但页面固定提交 `status: "DRAFT"`。

### 10.4 状态切换

保留：

```ts
onSetProductStatus(input: { id: number; status: ProductStatus })
```

服务端不能只按 ID 更新。上架时必须重读或在服务层校验商品完整性；并发敏感条件应进入更新条件或事务性业务流程。

### 10.5 错误码

预期业务失败使用 `appError()` 和稳定 `UPPER_SNAKE_CASE` 错误码，不直接向客户端暴露数据库异常。最低包括：

```text
PRODUCT_ID_INVALID
PRODUCT_NOT_FOUND
PRODUCT_NAME_REQUIRED
PRODUCT_NAME_TOO_LONG
PRODUCT_CATEGORY_REQUIRED
PRODUCT_CATEGORY_INVALID
PRODUCT_SLUG_INVALID
PRODUCT_SLUG_CONFLICT
PRODUCT_PRICE_INVALID
PRODUCT_BUY_RANGE_INVALID
PRODUCT_DESCRIPTION_TOO_LONG
PRODUCT_DESCRIPTION_INVALID
PRODUCT_COVER_IMAGE_INVALID
PRODUCT_FIXED_DELIVERY_CONTENT_REQUIRED
PRODUCT_PHYSICAL_STOCK_INVALID
PRODUCT_PUBLISH_REJECTED
```

所有新增错误码同步添加到 `lib/error-messages.ts`，页面不得新增私有 `messageFor()`。

## 11. 前端请求和反馈

所有商品管理 Telefunc 必须通过：

```ts
runTelefunc()
```

推荐行为：

- 创建草稿成功：“商品草稿已创建。”；
- 完整创建成功：“商品已创建。”；
- 编辑成功：“商品已保存。”；
- 状态切换成功：“商品状态已更新。”；
- 失败由统一错误码映射显示脱敏 Toast；
- `catch` 不重复显示错误；
- `finally` 恢复 loading/saving；
- 初始列表加载完全失败且页面无法工作时才使用页面级 `Alert`；
- 不同时显示 Alert 和 Toast。

## 12. 推荐代码结构

```text
pages/@adminPath/catalog/products/
  +Page.vue                    # 列表查询、请求、Dialog 状态和业务反馈
  ProductEditorDialog.vue      # Dialog、VeeValidate 表单、模式与关闭保护
  ProductRichTextEditor.vue    # Tiptap 编辑器与媒体图片插入
  product-form.ts              # schema、类型、默认值和数据转换

server/catalog/
  admin.telefunc.ts            # 管理接口入口
  product-description.ts       # 富文本清洗和长度限制
  product-validation.ts        # 可复用的商品保存/发布业务校验（需要时拆出）
  public.ts                    # 公开商品投影
```

如果 `ProductEditorDialog.vue` 继续增长，可在页面目录新增仅供该页面使用的字段分区组件；在证明跨模块复用前，不提升到 `components/admin`。

组件职责：

- `+Page.vue` 负责数据、请求、查询状态、保存状态和刷新；
- Dialog/字段组件负责展示、输入、客户端校验状态和事件；
- 服务端负责鉴权、最终校验、清洗和数据库读写；
- 富文本组件不得直接调用商品业务 Telefunc。

## 13. 数据库与索引

本功能不新增商品列。现有 `product` 已具备：

- `description text`；
- `product_slug_unique`；
- `product_categoryId_idx`；
- `product_status_sort_idx`。

开发时应通过实际 SQL 查询计划和列表筛选实现检查现有索引是否足够。只有服务端分页查询证明需要组合索引时才修改 schema；不能仅为猜测性能提前堆叠索引。

因为 CFFK 未上线，如确需调整索引，直接更新最终 Drizzle schema 和初始 migration，不新增兼容 migration。

## 14. 安全边界

必须满足：

1. 管理商品列表、详情、保存和状态切换只允许唯一 root。
2. 客户端 Zod 不替代服务端校验。
3. 富文本保存前服务端清洗，不能只在浏览器清洗。
4. 列表响应不包含固定交付全文、描述全文或卡密全文。
5. 不将原始 HTML 清洗异常、SQL、堆栈或数据库错误发送给前端。
6. 未预期异常进入统一 Workers Observability。
7. 商品封面和描述图片只接受允许协议和站内媒体代理路径。
8. 对 `<script>`、事件属性、`javascript:`、iframe 和 Base64 图片进行专项测试。
9. 固定交付内容只在订单交付链路和单商品 root 编辑数据中使用，不在公开商品详情和列表响应展示。
10. 上下架和保存期间禁用重复提交。

## 15. 可访问性与响应式

- 所有字段使用 `FieldLabel` 和稳定 `id`；
- 错误字段设置 `data-invalid` 和 `aria-invalid`；
- 编辑器工具栏按钮具有中文 `aria-label` 和 `title`；
- 编辑器内容区具有可识别标签或 `aria-describedby`；
- 图片预览提供商品名称或明确的 alt；
- `Switch`、`Select`、`RadioGroup` 按 shadcn-vue 方式绑定；
- Dialog 可通过键盘操作，但脏表单阻止意外退出；
- 桌面端可双栏组织字段，窄屏使用单栏；
- Footer 始终可见，不要求滚动到末尾保存；
- 状态颜色遵循黑白灰、品牌蓝橙和语义 destructive 规范。

## 18. 最终验收标准

### 功能

- 快速添加只创建草稿，保存后关闭 Dialog 并刷新列表；
- 添加和编辑使用同一个完整 Dialog；
- 商品完整字段可保存并正确回显；
- 商品描述支持规定范围内的富文本和媒体图片；
- 公开商品详情正确展示富文本、购买说明和发货提示；
- 自动卡密、固定内容、人工和物流发货条件字段正确；
- 搜索、分类、状态筛选和分页全部由服务端驱动。

### 规范

- 商品表单使用 VeeValidate、Zod 和 shadcn-vue Field；
- 页面没有新增原生业务表单控件；
- 列表继续使用 `AdminDataTable` 和 `Pagination`；
- 页面标题来自 `AdminPageHeader` 和集中导航元数据；
- 新增/编辑不产生独立正式路由；
- 短暂反馈使用 Sonner Toast；
- 脏表单不能通过遮罩或 Escape 意外关闭。

### 安全

- 管理接口覆盖 guest/user/root；
- 恶意 HTML、事件属性和危险 URL 不会保存或执行；
- 列表响应不包含固定交付全文和完整描述；
- 原始异常、SQL、堆栈和敏感交付内容不泄露到客户端；
- 未预期异常进入 Workers Observability。

### 工程质量

- 修改文件 diagnostics 无 error/warning；
- `bun run lint` 不新增 warning 或 error；
- `bun run build` 通过；
- 相关 `bun test` 测试通过；
- 手动验证一个成功路径、一个输入错误路径和脏表单关闭确认路径。
